# Tailwind CSS v4 compatibility fixtures

These fixtures are the executable compatibility contract for Stillwind's
Tailwind v4 reimplementation. They deliberately use Tailwind's compiled CSS as
the oracle; Stillwind itself is never used to generate an expected result.

## Layout

```
fixtures/tailwind-v4/
  cases/*.fixture.md          # one reviewable Markdown file per capability
tools/regenerate-tailwind-v4-fixtures.ts
```

There is one fixture file per capability family, not one file per candidate.
That keeps the suite well below the 500-file budget while allowing hundreds of
cases. The regeneration tool enforces that ceiling.

## Case format

Each case is a heading followed by three fenced blocks:

````markdown
## `layout.display`

### Input CSS
```css
@import "tailwindcss";
```

### Candidates
```text
block inline-flex
```

### Expected CSS
```css
/* generated by tools/regenerate-tailwind-v4-fixtures.ts */
```
````

`Input CSS` is passed to the upstream compiler with only `source(none)` added
to its `tailwindcss` import. This disables automatic content detection, so a
case can never accidentally compile candidates from another fixture. The
`Candidates` block is then lowered to Tailwind's `@source inline(...)`
directive by the regeneration tool. The expected block is its formatted
compiler output and is the sole snapshot assertion target.

The input import may include other Tailwind v4 import modifiers such as
`prefix(...)` or an explicit `source(...)`; the oracle preserves them and
otherwise appends only `source(none)`.

Ordinary cases import `tailwindcss/theme` and `tailwindcss/utilities` directly,
so they never include Preflight. Cases named `reset.*` use the complete
`tailwindcss` import and preserve the raw compiler output as the dedicated
Preflight/reset compatibility contract. The generator never post-processes
compiler CSS.

## Upstream registration catalog

`tools/extract-tailwind-v4-registrations.ts` derives the exhaustive direct
registration catalog and its corresponding fixture from the pinned upstream
checkout. It does not add a dependency to this workspace.

```powershell
node tools/extract-tailwind-v4-registrations.ts --upstream C:\path\to\tailwindcss --write
vp run --filter @stillwind/tools fixtures:write
```

## Oracle policy

Regeneration calls the pinned `tailwindcss` compiler API directly from
`@stillwind/tools`; Stillwind compiler packages do not depend on Tailwind. A
release upgrade changes that package's development dependency and regenerates
every fixture in one reviewable commit.

Run:

```powershell
vp run --filter @stillwind/tools fixtures:write
vp run --filter @stillwind/tools fixtures:check
```

The second command verifies that checked-in expected CSS matches the oracle.
