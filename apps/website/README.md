# Stillwind website

The Astro site uses the workspace Stillwind integration and compiles its component styles from
`src/styles.css`. The integration injects compiled CSS into each document. The displayed diagnostics
and CSS are generated by the compiler at build time.

Run tasks from the repository root:

```sh
vp run @stillwind-internal/apps-website#dev
vp run @stillwind-internal/apps-website#build
vp run @stillwind-internal/apps-website#preview
vp run @stillwind-internal/apps-website#typecheck
vp run @stillwind-internal/apps-website#test
vp run @stillwind-internal/apps-website#verify
```

Development and preview use port 4322. The build writes a static site to `dist/`.

The application provides emnapi 1.x for Astro's checker. Stillwind's compiler bindings use their
own emnapi 2.x dependency.

`src/lib/scroll.ts` publishes normalized progress as `--scroll-progress`. `src/lib/code-morph.ts`
matches whole tokens within stable utility keys and publishes `--morph-progress`. Only spaces and
variant colons divide utility strings. CSS interpolates the measured positions, colors, and visibility
of those tokens. Utility wrappers keep variants and colons on one line and supply continuous
underlines. Each compiler report identifies its utility from the reported source range. Diagnostic
lines start just below the center of that utility's underline and follow its measured position.
Multiple explanations occupy separate horizontal ranges on wide canvases and stack below the
source on narrow canvases. Tracking uses passive events and one
animation frame per update. Both controllers release their browser subscriptions on disposal.

The four scenes share the heading "Write with confidence" and contain six complete states.
Normalize & Format shows Original, Normalized, and
Formatted expressions at the same position under one heading. Normalization replaces `px-[16px]`
with the compiler's canonical utility, and formatting sorts the utilities. Compile uses the full
canvas width for its input. Its output row places React props and CSS together below the input.
An independent overlay draws the arrow without affecting the output columns.
Each interval holds its starting and ending states for 30% each. The remaining 40% drives the
transition, so complete states occupy 60% of the scroll range. Navigation moves smoothly to each
complete state, and ordinary scrolling follows the user's input.
The code remains selectable as the nearest complete source state.
The style showcase spans four viewport heights of scroll.

The style showcase pins its presentation at widths of at least 320 pixels, with no reduced-motion
preference. It requires a height of 760 pixels below 640 pixels wide and 720 pixels at larger widths.
Smaller viewports, reduced motion, and disabled JavaScript show the specimens in order.
Static findings place each marked utility and its connected explanation on a separate row.
Static Normalize & Format shows all three expressions. Static Compile places CSS to the
right of the props when the viewport is at least 720 pixels wide and stacks them on smaller screens.

The feature section shares one heading and uses vertical navigation at widths of at least 1120
pixels and horizontal navigation below that width. Syntax grows from one utility string through conditions, arrays,
CSS states, variant groups, nesting, and custom properties. Relationships shows a named container,
explicit ref scopes, and CSS Anchor Positioning. The container and scoped examples use article
cards. Motion shows an entrance animation and separate View Transition participants for an article's
thumbnail, title, and metadata. `src/lib/features/scenes.ts` gives each
example its own scroll interval and complete demonstration range. Source changes occupy separate
gaps. Desktop Syntax moves shared words. Punctuation stays visible when its text and measured position
match; other punctuation fades in place. Compact layouts, Relationships, and Motion replace complete snippets.
Each example supplies its own explanation below the shared heading. Measured highlights identify
the focus text without line breaks or indentation, and connectors start at its center.
The feature examples span 10.95 viewport heights of scroll. Syntax holds each source for 0.5,
container and scope examples for 1, Anchor Positioning for 1.4, and Motion examples for 1.2.
Source changes use separate 0.15 intervals.

Each source example owns its explanation and matching UI through `FeatureSource.astro` and
`FeaturePreview.astro`. Compact layouts show code above a centered UI below 840 pixels and place
them side by side at larger widths. The compact heading appears once before the pinned examples.
Phone layouts replace the small example markers with Previous and Next buttons.
The minimum heights for pinning are 800 pixels below 640 pixels wide, 900 pixels from 640 to 839,
740 pixels from 840 to 1119, and 720 pixels at larger widths. Shorter viewports keep all pairs in
document flow and scrub each UI as it crosses the viewport. Reduced motion and disabled JavaScript
show all pairs without scroll animation.

The previews use the actual Astro macro API. Buttons let visitors resize the container, toggle
attributes, move the anchor, and replay the motion demos. The container ref sits outside the card's
border and padding, so the query and width gauge measure the complete card from 300px to 180px.
Narrow screens reduce the starting width to the largest multiple of 10 pixels that fits.
Keyframes and View Transitions share
a preview stage, a progress rail, and replay controls. The anchor preview moves a Save button around
a visible container. Native CSS shifts the attached label sideways and flips it above the button
when it reaches the container's lower edge. Scrolling scrubs the compiled CSS keyframes.
The View Transition illustration interpolates each participant between measured list and article
layouts; it does not require the native transition API. Each motion example has its own progress
rail in the sequential presentation. Without JavaScript, manual controls are hidden or disabled.
Manual replay keeps its final state until scrolling reaches 100%, its stage leaves the viewport,
or a scene change makes it completely invisible. Those conditions resume scroll control and
interrupt any remaining manual playback. Scrolling back to 0% keeps the manual state while visible.

The setup section links framework imports to the integration guides and states the Tailwind CSS,
CVA, and explicit CSS export boundaries.

The header occupies 64 pixels at the top. It returns as a 56-pixel fixed bar when the style
showcase reaches the viewport top. Pinned presentations reserve room for the bar.

Fontsource supplies Instrument Sans at weights 400 and 500 for headings and body text.
Code uses the official [JetBrains Mono v2.304](https://github.com/JetBrains/JetBrainsMono/releases/tag/v2.304)
Regular WOFF2 in `src/assets/fonts/`. Its `zero` OpenType feature supplies slashed zero and must
remain available when replacing the font file. The face enables that feature by default.
The build bundles both families for local delivery and preloads their regular faces.
Their licenses are available under `public/fonts/`. Code ligatures are disabled so measured
punctuation stays aligned with the source. Font loading remeasures source tokens, highlights,
and connectors.
