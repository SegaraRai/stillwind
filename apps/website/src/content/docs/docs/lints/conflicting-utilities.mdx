This rule reports two utilities that set the same CSS property under the same
conditions. Only one of them takes effect. The order of the generated CSS decides
which one, not the order in your code, so the code does not show the result.

## Reported

<DiagnosticExample code="conflicting-utilities">

```tsx
style("p-2 p-4");
```

</DiagnosticExample>

## Fixed

```tsx
style("p-4");
```

## How to fix

- Keep the utility that you want, and remove the other.
- If the values belong to different states or widths, add a variant to one of
  them, such as `p-2 md:p-4`.
- If one utility overrides a shared style, pass the shared style as a base. See
  [Override a style](/docs/guides/style#override-a-style).
- If a physical utility such as `ml-4` meets a logical utility such as `mx-auto`,
  use logical utilities for both or physical utilities for both. The writing mode
  decides how physical and logical properties overlap.

Some pairs do not conflict because one utility reads a custom property that the
other utility sets to the value it writes, so the order does not change the result:

- A side utility, such as `border-t` or `divide-y`, and a style utility, such as
  `border-dashed` or `divide-dashed`
- A font size utility, such as `text-sm`, and a `leading-*` utility

A physical utility and a logical utility conflict only when they set the same
side in one of the writing modes that `writingModes` lists. By default, the rule
checks horizontal writing modes only, so `px-2 pt-2` does not conflict, but
`mx-auto ml-4` does.

When a physical utility meets a logical utility, the finding also shows how to
use logical properties for both. It names a logical utility from your design
system that writes the same value, such as `pbs-2` for `pt-2`, with the sides of
horizontal left-to-right writing modes. The finding does not prefer logical
properties; you can also replace the logical utility with physical utilities. It
names no utility when `writingModes` does not include `horizontal-tb`.

## Options

`allowShorthandOverrides` allows the supported overrides between a shorthand
utility and a longhand utility. The rule still reports other conflicts.

`writingModes` lists the CSS `writing-mode` values in which the rule compares
physical and logical utilities: `horizontal-tb`, `vertical-rl`, and
`vertical-lr`. The rule checks both the left-to-right and the right-to-left
direction of each mode. `sideways-rl` and `sideways-lr` place the sides as
`vertical-rl` and `vertical-lr` do. The default is `["horizontal-tb"]`, and the
`stylistic` preset lists all three. Add the vertical modes if your pages use
vertical text:

```ts
const rules = {
  "conflicting-utilities": {
    writingModes: ["horizontal-tb", "vertical-rl"],
  },
};
```

Utilities that conflict in every writing mode, such as `p-2 px-4`, are reported
even when the list is empty.

`ignoredUtilities` lists utility names whose pairs the rule does not report.
Use it for a base class that a component library expects you to combine with
modifier classes. For example, daisyUI expects `btn` with `btn-outline` or
`btn-ghost`:

```ts
const rules = {
  "conflicting-utilities": {
    ignoredUtilities: ["btn"],
  },
};
```

The rule then reports neither `btn btn-outline` nor `btn btn-ghost`, but it
still reports `btn-outline btn-ghost`. Each entry is a complete,
case-sensitive glob that accepts `*` and `?`. The rule matches it against the
utility name without variants and the `!` modifier, so `btn` also covers
`hover:btn` and `btn!`. A pair is not reported when either utility matches. A
glob such as `btn*` also matches `btn-outline` and `btn-ghost`, so list base
classes by their full names. The default is an empty list.
[Plugins](#plugins) lists the base classes of common plugins.

## Plugins

Some plugins define a base class that you combine with modifier classes on the
same element, such as `btn btn-outline` in daisyUI. When both classes set the
same property, the rule reports the pair, although the plugin intends the
modifier to win. The following settings stop these reports for the plugins that
[Tailwind CSS compatibility](/docs/guides/tailwind-compatibility#plugins-and-css-packages)
lists:

| Package                                        | Setting                                             | Pairs that the setting allows                            |
| ---------------------------------------------- | --------------------------------------------------- | -------------------------------------------------------- |
| `daisyui`                                      | `ignoredUtilities: ["btn", "join"]`                 | `btn btn-outline`, `btn btn-ghost`, `join join-vertical` |
| `@tailwindcss/typography`                      | `ignoredUtilities: ["prose"]`                       | `prose prose-lg`, `prose prose-invert`                   |
| `@tailwindcss/forms` with the `class` strategy | `ignoredUtilities: ["form-*"]`                      | `form-input px-4`, `form-select rounded-full`            |
| `tailwind-scrollbar`                           | `ignoredUtilities: ["scrollbar", "scrollbar-thin"]` | `scrollbar scrollbar-thumb-sky-700`                      |
| `tailwindcss-motion`                           | `ignoredUtilities: ["motion-preset-*"]`             | `motion-preset-fade motion-duration-2000`                |
| `tailwindcss-animate`                          | `ignoredUtilities: ["animate-in", "animate-out"]`   | `animate-in fade-in`, `animate-in duration-300`          |
| `tailwindcss-animated`                         | `allowShorthandOverrides: true`                     | `animate-fade animate-duration-1000`                     |
| `tw-animate-css`                               | `allowShorthandOverrides: true`                     | `animate-in delay-150`, `animate-in repeat-infinite`     |

The other packages on that page need no setting. In these packages, the rule
reports only pairs of alternative classes, such as `h-radix-select-trigger h-10`.

`tailwindcss-animated` and `tw-animate-css` write the `animation` shorthand in
an animation class and an `animation-*` longhand in a modifier class, so
`allowShorthandOverrides` allows these pairs without hiding other pairs of the
animation class.

If you use several plugins, put all their entries in one list:

```ts
const rules = {
  "conflicting-utilities": {
    ignoredUtilities: ["btn", "join", "prose"],
  },
};
```

An ignored base class also hides the pairs that do conflict, such as
`animate-in animate-out` or `scrollbar scrollbar-thin`. Check these pairs in
review.
