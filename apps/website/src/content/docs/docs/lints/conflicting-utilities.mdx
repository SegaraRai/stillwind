This rule reports two utilities that set the same CSS property under the same
conditions. Only one of them takes effect. The order of the generated CSS decides
which one, not the order in your code, so the code does not show the result.

## Reported

<DiagnosticExample code="conflicting-utilities">

```tsx
style("p-2 p-4");
```

</DiagnosticExample>

## Fixed

```tsx
style("p-4");
```

## How to fix

- Keep the utility that you want, and remove the other.
- If the values belong to different states or widths, add a variant to one of
  them, such as `p-2 md:p-4`.
- If one utility overrides a shared style, pass the shared style as a base. See
  [Override a style](/docs/guides/style#override-a-style).
- If a physical utility such as `pt-2` meets a logical utility such as `px-2`, use
  logical utilities for both or physical utilities for both. The writing mode
  decides how physical and logical properties overlap.

Some pairs do not conflict because one utility reads a custom property that the
other utility sets to the value it writes, so the order does not change the result:

- A side utility, such as `border-t` or `divide-y`, and a style utility, such as
  `border-dashed` or `divide-dashed`
- A font size utility, such as `text-sm`, and a `leading-*` utility

When a physical utility meets a logical utility, the finding also shows how to
use logical properties for both. It names a logical utility from your design
system that writes the same value, such as `pbs-2` for `pt-2`, with the sides of
horizontal left-to-right writing modes. The finding does not prefer logical
properties; you can also replace the logical utility with physical utilities.

## Options

`allowShorthandOverrides` allows the supported overrides between a shorthand
utility and a longhand utility. The rule still reports other conflicts.
