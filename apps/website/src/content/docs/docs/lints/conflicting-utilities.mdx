This rule reports two utilities that set the same CSS property under the same
conditions. Only one of them takes effect. The order of the generated CSS decides
which one, not the order in your code, so the code does not show the result.

## Reported

<DiagnosticExample code="conflicting-utilities">

```tsx
style("p-2 p-4");
```

</DiagnosticExample>

## Fixed

```tsx
style("p-4");
```

## How to fix

- Keep the utility that you want, and remove the other.
- If the values belong to different states or widths, add a variant to one of
  them, such as `p-2 md:p-4`.
- If one utility overrides a shared style, pass the shared style as a base. See
  [Override a style](/docs/guides/style#override-a-style).
- If a physical utility such as `pt-2` meets a logical utility such as `px-2`, use
  logical utilities for both, such as `pbs-2`. The writing mode decides how
  physical and logical properties overlap.

A utility that sets a side, such as `border-t` or `divide-y`, and a style utility,
such as `border-dashed` or `divide-dashed`, do not conflict. The side reads the
style through a custom property that the style utility also sets.

## Options

`allowShorthandOverrides` allows the supported overrides between a shorthand
utility and a longhand utility. The rule still reports other conflicts.
