This rule reports a suppression comment that the CLI cannot read, such as a
comment with a misspelled rule name. The comment suppresses nothing, so the
finding that you meant to hide still appears.

## Reported

<DiagnosticExample code="invalid-lint-suppression">

```tsx
// swlint-disable-next-line no-arbitary-colors -- Partner brand color.
style("bg-[#123456]");
```

</DiagnosticExample>

## Fixed

```tsx
// swlint-disable-next-line no-arbitrary-colors -- Partner brand color.
style("bg-[#123456]");
```

## How to fix

- Correct the rule name. The [lint rule reference](/docs/lints) lists every
  name.
- Check the form of the comment: `swlint-disable-next-line`, `swlint-disable-line`,
  or a `swlint-disable` and `swlint-enable` pair, followed by rule names.

See [Suppression comments](/docs/configuration#suppression-comments).
