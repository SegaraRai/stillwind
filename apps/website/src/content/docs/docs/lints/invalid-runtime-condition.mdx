---
title: invalid-runtime-condition
description: Reports a runtime CSS condition that the compiler cannot compile in its position.
slug: docs/lints/invalid-runtime-condition
---

This rule reports a runtime CSS condition, such as `--if()`, that the compiler
cannot express with the supported CSS. Comparisons of custom-property values,
for example, need the native CSS `if()` function and `useCssIf: true`. The
message explains why the condition failed. The declaration produces no CSS.

## Reported

<DiagnosticExample code="invalid-runtime-condition">

```tsx
const fade = style.keyframes({ to: "[color:--if(--mode:compact,red,blue)]" });
style(fade("duration-300"));
```

</DiagnosticExample>

## Fixed

```tsx
const fade = style.keyframes({ to: "text-(color:--frame-color)" });
style("[--frame-color:--if(--mode:compact,red,blue)]", fade("duration-300"));
```

```ts title="stillwind.config.ts"
import { defineConfig } from "stillwind/config";

export default defineConfig({
  projects: [
    {
      css: "./src/stillwind.css",
      files: ["src/**/*.{ts,tsx}"],
      useCssIf: true,
    },
  ],
});
```

## How to fix

- Move the condition onto the element, and let the keyframes read the result
  through a custom property, as in the example. This keeps `--mode` as the
  source of the condition and keeps the same red and blue values.
- Enable `useCssIf: true` for comparisons of custom-property values, as in the
  configuration above. The browsers that you support must implement CSS `if()`.
- If the message names another unsupported condition, rewrite that condition or
  set the resulting custom property in JavaScript.

A condition that only needs `useCssIf` is reported by
[runtime-condition-requires-css-if](/docs/lints/runtime-condition-requires-css-if/)
instead.
